CHALLENGE 1 RESULT

A. Original vulnerability
- exact file: src/app/api/listings/owned/route.ts
- exact line(s): Line 32 (in POST handler)
- what was wrong: The UPDATE query only filtered by `ownedProxies.id` (the record ID) but did NOT verify that the record belongs to the current session user (`sessionUser.id`). This allowed an authenticated user to update the `locked` status of ANY owned proxy record by knowing its ID, regardless of ownership.

B. Root cause
- The WHERE clause in the UPDATE statement was `eq(ownedProxies.id, id)` only. It lacked a condition to ensure `ownedProxies.userId === sessionUser.id`. Since the `ownedProxies` table has a `userId` column referencing the owner (per schema.ts line 244), the query should have enforced ownership. Without this check, User A could send a request with User B's owned proxy ID and modify User B's record.

C. Change made
- exact file changed: src/app/api/listings/owned/route.ts
- concise description of the modification: 
  1. Added `and` to the drizzle-orm import (line 4)
  2. Modified the UPDATE WHERE clause from `eq(ownedProxies.id, id)` to `and(eq(ownedProxies.id, id), eq(ownedProxies.userId, sessionUser.id))` (line 32)
  This ensures the update only affects records that match BOTH the requested ID AND belong to the current authenticated user.
